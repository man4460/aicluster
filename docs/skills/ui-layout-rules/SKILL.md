# กฎ UI ของโปรเจกต์ (ผู้ใช้กำหนด)

## 1. ห้ามแบ่งหน้าจอเป็น 2 คอลัมน์
- **ห้าม** ใช้ `grid lg:grid-cols-[1fr_22rem]` หรือ side panel ถาวร
- ให้เนื้อหาหลัก (ตาราง/ผัง/รายการ) **เต็มความกว้าง**
- แผงข้อมูลเสริม (รายละเอียด/เครื่องมือ) ให้เป็น **overlay ลอยมุมขวา** (`absolute right-2 top-2 w-64`)
  หรือ `details/summary` ที่ผู้ใช้กดเปิดเอง — ไม่กินพื้นที่ถาวร

## 2. ฟอร์มกรอกข้อมูล → ปุ่ม + popup
- ปุ่มหลักอยู่แถบหัว: `+ เพิ่ม...` / `+ บันทึก...` / `+ เขียน...`
- ฟอร์มทั้งหมดอยู่ใน modal (`fixed inset-0 z-50 bg-slate-900/40` + การ์ด `max-w-md`)
  เปิดด้วย `useState<null | "suspect" | "log" | "report">`
- ปิดด้วย Escape + คลิกฉากหลัง (ใส่ `useEffect` ฟัง keydown)
- ฟิลด์ที่เลือกได้หลายค่า → **checkbox list** ไม่ใช่ `<select multiple>` (กดยากบนมือถือ)

## 3. คำอธิบายสั้น
- ห้ามเขียนคำอธิบายใต้หัวข้อถ้าไม่จำเป็น
- ใช้ label สั้น + ข้อมูลจริงเป็นตัวอธิบาย
- แถบเครื่องมือ: ปุ่ม + ตัวเลขสรุป (ไม่ใช่ย่อหน้าอธิบาย)

## 4. ตาราง
- หัวตารางต้องตรงกับค่าจริง และใส่หน่วยในช่อง (`3 คดี`, `2 จุด`)
- ใช้ `sticky top-0` ที่หัวตารางเมื่อเลื่อน

## 5. ตรวจงาน UI
- **ต้อง** เปิดดูภาพจริงด้วย `browser-automation` ก่อนบอกว่าเสร็จ (typecheck ไม่พอ)
- ตรวจ: ปุ่มขึ้นไหม · popup เปิด/ปิดได้ · ตารางกว้างเท่าไร · console error 0

## 6. ข้อผิดพลาดที่เคยทำ (อย่าทำซ้ำ)
- เขียนโมเดล Prisma ซ้ำโดยไม่ grep ก่อน → validate พัง 9 จุด
- ใช้ `redirect()` ใน API route → 500 (ต้องใช้ `requireModuleApi()`)
- ประกาศเกณฑ์ตรวจจากสมมติฐาน (เช่น hub ต้องเป็นคนที่ 1) → ต้องตรวจตามหลักทฤษฎี
- ใช้ label propagation ทำ community → ยุบทั้งกราฟเป็นกลุ่มเดียว ต้องใช้ Louvain
- วาง node กราฟทับกันเพราะจัดวงกลมรัศมีใกล้กัน → ต้องแยกชั้น (คดีกลาง/บุคคลวงใน/สถานที่วงนอก)
